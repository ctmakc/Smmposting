# Autonomous Content Factory — Technical Specification

> Production-grade, Python. Управляющий документ проекта.

## 0. Цель системы

Полностью автономная масштабируемая backend-система, которая:

1. Самостоятельно анализирует тренды и контент в заданной нише
2. Выявляет контент-гэпы
3. Формирует контент-стратегию
4. Генерирует сценарии и ассеты
5. Публикует контент
6. Анализирует метрики
7. Корректирует стратегию в замкнутом цикле
8. Работает устойчиво 24/7 без ручного участия, кроме явных approval-точек

## 2. Компоненты системы

### 2.1. API Gateway

- **Технологии:** FastAPI + Pydantic v2
- **Назначение:**
  - Управление брендами и политиками
  - Ручной запуск workflow
  - Approve/reject контента
  - Просмотр статусов, логов, метрик

### 2.2. Workflow Engine

- **Технологии:** Temporal (Python SDK)
- **Требования:**
  - Каждая идея, сценарий, публикация — отдельный workflow
  - Гарантированное продолжение после падений
  - Таймеры 2h / 24h / 72h
  - Idempotency
  - Ручные сигналы approve/reject

### 2.3. Worker Services

| Worker | Назначение |
|---|---|
| `ingest` | Сбор трендов, конкурентов, комментариев |
| `analyze` | Кластеризация, паттерны, гэпы |
| `generate` | Сценарии, тексты, captions |
| `media` | Сборка видео/сабов (если включено) |
| `publish` | Автопостинг и проверка |
| `metrics` | Сбор метрик |
| `community` | Автоответы на комментарии |

Все воркеры масштабируются независимо.

### 2.4. Хранилища

| Хранилище | Назначение |
|---|---|
| **Postgres** | Все сущности, статусы, метрики, аудит, эксперименты |
| **Object Storage (S3)** | Видео, изображения, сабы, project files |
| **Vector DB** | Brand memory, контент-архив, similarity search, anti-repeat |

## 6. Скоринг

### 6.1. PriorityScore (0–100)

```
0.35 * TrendScore
+ 0.25 * GapScore
+ 0.20 * BrandFit
+ 0.10 * EffortInverse
+ 0.10 * ConversionIntent
```

### 6.2. RiskScore (0–100)

```
0.30 * ClaimRisk
+ 0.25 * CompetitorRisk
+ 0.15 * PolicyViolation
+ 0.15 * Ambiguity
+ 0.15 * PlatformRisk
```

## 7. Автопубликация (строгие правила)

Автопостинг разрешён **ТОЛЬКО если:**

- `risk_score ≤ policy.risk_threshold_auto_publish`
- `qc_status = APPROVED`
- Нет unverified claims
- Нет упоминаний конкурентов (если запрещено)
- Нет гарантий/доходностей/медицинских/юридических обещаний

Иначе → `NEEDS_APPROVAL`.

## 10. Деплой

**MVP:** docker-compose, 1 сервер

**Scale:** Kubernetes (k3s или managed), горизонтальное масштабирование воркеров

## 11. Обязательные нефункциональные требования

1. Детерминированные workflow
2. Idempotent операции
3. Полный аудит
4. Отсутствие "магии" без логов
5. Любая автоматизация отключаема флагом
6. Вся логика — кодом, не хардкод

## 12. Конечный результат

Система, которая:

- Сама решает **что** публиковать
- Сама решает **когда** публиковать
- Сама решает **что сработало**
- Сама корректирует стратегию
- Масштабируется простым добавлением воркеров
- Не требует постоянного ручного управления
